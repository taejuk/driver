## §0. 문서 규약

### 0.1 요구 수준

RFC 2119를 따른다.

| 용어                | 의미                            |
| ------------------- | ------------------------------- |
| MUST / MUST NOT     | 위반 시 동작 미정의             |
| SHOULD / SHOULD NOT | 강한 권고. 위반하려면 근거 필요 |
| MAY                 | 선택 사항                       |

### 0.2 출처 태그

모든 요구사항에 아래 태그를 붙인다.

| 태그   | 의미                                             |
| ------ | ------------------------------------------------ |
| `[HW]` | 하드웨어가 강제하는 제약. 드라이버에 선택권 없음 |
| `[SW]` | 소프트웨어 규약. 다르게 설계할 수도 있었음       |

`[SW]` 항목에는 **왜 그렇게 정했는지 한 줄**을 반드시 덧붙인다.
근거를 못 쓰겠으면 그건 `[SW]`가 아니라 미결정 사항이다 → §9로 보낸다.

### 0.3 요구사항 ID

형식: `NACC-REQ-nnn` (3자리, 순번, 재사용 금지)

삭제된 요구사항은 번호를 비우지 말고 `(삭제됨: 사유)`로 남긴다.
드라이버 코드 주석과 테스트에서 이 ID를 참조한다.

```c
/* NACC-REQ-014: doorbell 쓰기 전 디스크립터 가시성 보장 */
dma_wmb();
writel(prod, base + NACC_REG_DOORBELL);
```

### 0.4 레지스터 필드 속성

| 표기   | 의미                                |
| ------ | ----------------------------------- |
| `RO`   | 읽기 전용. 쓰기는 무시              |
| `RW`   | 읽기/쓰기                           |
| `RW1C` | 1을 쓰면 클리어. 0을 쓰면 변화 없음 |
| `WO`   | 쓰기 전용. 읽으면 0                 |
| `RSVD` | 예약. §4.4 정책 적용                |

### 0.5 비트 표기

- 비트 범위: `[31:24]` (MSB:LSB)
- 단일 비트: `[7]`
- 예약값: `0`
- 미정의: `X`

## §4. 전역 접근 규칙

> 이 절이 빠진 데이터시트는 반드시 이식 버그를 만든다.
> §5를 쓰기 전에 여기를 먼저 확정한다.

### 4.1 접근 폭

**NACC-REQ-010** `[HW]` 모든 레지스터는 32비트 정렬 접근만 허용한다(MUST).
8/16비트 접근의 동작은 미정의다.

**NACC-REQ-011** `[HW]` 64비트 값을 담는 레지스터 쌍(`_LO` / `_HI`)은
단일 접근만을 허용한다. 만약 값을 LO나 HI만 변경하고 싶으면 읽은 뒤 다시 다 써야 한다(MUST).

### 4.2 엔디안

**NACC-REQ-012** `[HW]` MMIO 레지스터는 리틀엔디안이다.
드라이버는 `readl()` / `writel()`을 사용해야 한다(MUST).

**NACC-REQ-013** `[HW]` 호스트 메모리의 디스크립터 필드도 리틀엔디안이다.
드라이버는 `cpu_to_le32()` 계열 변환을 사용해야 한다(MUST).

> 두 문장을 분리해서 쓴다. MMIO와 디스크립터의 엔디안이 다른 하드웨어가
> 실제로 존재한다.

### 4.3 순서 및 배리어

**NACC-REQ-014** `[HW]` 디바이스는 디스크립터 링 메모리의 내용과
doorbell 레지스터 쓰기 사이의 순서를 보장하지 않는다. 드라이버는
doorbell을 쓰기 전에 디스크립터 쓰기가 메모리에 보이도록 해야 한다
(MUST, `dma_wmb()`).

**NACC-REQ-015** `[HW]` 서로 다른 MMIO 레지스터에 대한 연속 쓰기는 프로그램 순서대로 디바이스에 도달하는가?
순서대로 동작하지 않는다. 그래서 필요할 때마다 wmb를 써서 사용.
TODO: 완료 인터럽트를 받은 뒤 결과 데이터를 읽을 때 필요한 배리어
(`dma_rmb()`)를 요구사항으로 추가한다.

### 4.4 예약 필드 정책

**NACC-REQ-016** `[SW]` 예약(`RSVD`) 필드는 read-modify-write 보존 방식을
따른다. 드라이버는 레지스터를 쓸 때 예약 비트의 기존 값을 보존해야 한다(MUST).
읽을 때 예약 비트의 값은 무시해야 한다(MUST).

> 근거: 미래 리비전에서 예약 비트를 사용하게 되더라도 구버전 드라이버가
> 해당 비트를 0으로 밀어버리지 않는다.
>
> 대안이었던 `RAZ/WI`(읽으면 0, 쓰면 무시)는 하드웨어 구현이 더 단순하지만
> 확장 시 호환성을 잃는다. §2.4의 "추가만 허용" 정책과 맞지 않아 기각.

### 4.5 정렬 및 미매핑 영역

**NACC-REQ-017** `[HW]` BAR0 내에서 레지스터가 정의되지 않은 오프셋에 대한

## §9. 미해결 질문

> **빈칸으로 두지 않고 질문으로 명시한다.**
> 답을 정하면 해당 항목을 본문으로 옮기고 여기서 삭제한다.

### Q1. `CTRL.ENABLE` ← 0 시 진행 중인 명령의 운명

**선택지**

- (a) 즉시 폐기. 하드웨어는 DMA를 중단하고 `READY`/`RESET`으로 간다
- (b) 진행 중 명령 완료까지 대기 후 정지 (drain)
- (c) 미정의

**영향 범위**

- `nacc_remove()`의 quiesce 시퀀스
- M3의 FLR 설계 — 여기서 (b)를 고르면 FLR도 drain 의미론을 가져야 일관됨
- (a)를 고르면 드라이버는 in-flight 버퍼를 언제 해제해도 안전한지 알아야 함
  → DMA가 확실히 멈췄음을 알리는 상태 비트가 필요

**현재 판단:** 미정

---

### Q2. `ERROR` 진입 시 링 인덱스 보존 여부

**선택지**

- (a) 보존. 드라이버가 오류 지점을 식별하고 재개 가능
- (b) 미보존. 전체 재초기화만 가능

**영향 범위**

- §8.2 오류 모델
- `ERROR` 상태의 탈출 경로 (T7)
- (b)를 고르면 오류가 곧 링 재생성이므로 §6.3 소유권 규칙이 단순해짐

**현재 판단:** 미정

---

### Q3. MSI 벡터 개수

**선택지**

- (a) 1개. 완료와 오류를 `IRQ_STATUS` 비트로 구분
- (b) 2개 이상. 벡터별 핸들러 분리

**영향 범위**

- ISR 구조. (a)면 핸들러 하나에서 원인 분기, (b)면 핸들러 복수
- 나중에 (a)→(b)로 바꾸면 드라이버 구조가 바뀜
- M1 단순성 관점에서는 (a)가 유리

**현재 판단:** 미정
